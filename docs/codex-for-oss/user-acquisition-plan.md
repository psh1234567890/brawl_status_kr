# 이용자 확보와 커뮤니티 피드백 계획

- 작성일: 2026-07-25
- 목표 기간: 공개 준비가 끝난 뒤 6주
- 원칙: 가짜 사용자·별·이슈·PR을 만들지 않고, 실제 사용과 공개 유지보수 기록만 측정한다.

## 핵심 판단

이 서비스는 검색이 곧 데이터 수집이다. 따라서 홍보의 성공은 단순 페이지뷰가 아니라 다음 순환을 만드는 것이다.

```text
관련 검색·커뮤니티 글
→ 사이트 방문
→ 플레이어 태그 검색 성공
→ 최근 전투 저장·표본 개선
→ 더 유용한 맵·팀·카운터 정보
→ 즐겨찾기·공유·재방문
→ 오류 제보와 공개 수정
```

현재는 고유 방문자·성공 검색·재방문을 구분해 측정하지 않으므로 “이용자 수”를 사실로 말할 수 없다. 라이브 상태 페이지의 `130 검색 플레이어`는 저장된 고유 태그 수이지 사용자 수가 아니다.

## 1. 측정 가능한 퍼널

| 단계 | 지표 | 의미 | 금지 |
| --- | --- | --- | --- |
| 유입 | 캠페인별 landing session, Search Console click, referrer | 어디서 방문했는가 | 태그를 UTM에 넣지 않기 |
| 활성화 | `search_succeeded` / `search_started` | 실제 프로필 검색에 성공했는가 | 실패를 사용자로 세지 않기 |
| 데이터 기여 | 새 고유 태그, 새 battle fingerprint, 중복 무시 수 | 표본이 얼마나 개선됐는가 | 사용자 수로 부르지 않기 |
| 재방문 | 7일 내 재방문 브라우저, 반복 성공 검색 | 다시 쓸 이유가 있었는가 | 로그인 없는 수치를 사람 수로 단정하지 않기 |
| 피드백 | 실제 이슈·Discussion·데이터 제보, 응답 시간 | 유지보수 관계가 생겼는가 | 운영자 본인의 가짜 외부 이슈 금지 |
| 기여 | 외부 PR, 문서 수정, 재현 가능한 버그 리포트 | OSS 생태계 가치 | 계정 돌려쓰기 금지 |

권장 이벤트 이름은 `page_view`, `search_started`, `search_succeeded`, `search_failed`, `feedback_opened`, `github_opened`, `share_clicked`다. 분석 이벤트에는 플레이어 태그·이름·이메일을 넣지 않는다.

## 2. 우선순위 채널

### A. 검색 유입 — 가장 지속 가능한 1순위

이미 존재하는 `/meta`, `/maps`, `/brawlers`, `/teams`, `/counters`, `/skins`를 각각 실제 검색 의도에 맞는 유용한 페이지로 만든다.

- 브롤스타즈 전적 검색
- 브롤스타즈 맵 추천
- 브롤스타즈 브롤러 카운터
- 브롤스타즈 팀 조합
- 브롤스타즈 스킨 가격·목록
- 브롤스타즈 현재 맵·이벤트

각 페이지는 고유한 한국어 제목·설명·본문을 갖고, 데이터 출처·업데이트 시점·표본 한계를 함께 보여준다. 검색어만 바꾼 얇은 페이지나 자동 생성 문서 대량 생산은 하지 않는다. sitemap·canonical·robots·Search Console을 확인하고, 검색 클릭→성공 검색 전환을 측정한다.

Google Search Central은 명확한 제목·설명, 이해하기 쉬운 URL, 유용한 콘텐츠, Search Console 검증을 권장한다. 참고: <https://developers.google.com/search/docs/fundamentals/seo-starter-guide>

### B. Brawl Stars 커뮤니티 — 빠른 피드백 2순위

후보는 국내 Brawl Stars 게시판·카페·Discord, 게임 통계 도구를 소개할 수 있는 커뮤니티다. 정확한 게시판은 게시 시점에 활동성과 홍보 규칙을 다시 확인한다.

게시 원칙:

- 광고가 아니라 “개인 프로젝트 공개 + 사용성·정확성 피드백 요청”으로 쓴다.
- 공식 통계나 전체 유저 대표 표본이라고 하지 않는다.
- 링크 하나, 핵심 기능 3개, 알려진 한계 1개, 원하는 피드백 2개로 끝낸다.
- 같은 내용의 반복 도배를 하지 않는다.
- 댓글의 버그를 실제 GitHub 이슈로 옮길 때 작성자 동의와 개인정보를 확인한다.
- 업데이트가 있을 때만 후속 글을 쓴다.

### C. 짧은 사용 사례 콘텐츠 — 검색과 공유를 연결

주 1회 이하로 다음과 같은 실제 사용 사례를 만든다.

- “내 태그로 최근 25전과 누적 DB 기록이 왜 다를까?”
- “맵 추천의 5판 최소 표본은 무슨 뜻일까?”
- “팀전은 왜 참가자 전체를 펼쳐 계산할까?”
- “카운터 수치가 공식 전체 통계가 아닌 이유”

한 장짜리 요약 이미지나 30~60초 화면 녹화는 사이트 기능을 그대로 보여주고 과장된 승률 보장을 하지 않는다. 영상 제작자·클럽 운영자에게 연락하는 일은 사용자 승인 후 진행한다.

### D. 오픈소스 개발자 유입 — 사용자 획득과 별도 트랙

- GitHub description, canonical homepage, topics 정리
- `good first issue`, `help wanted`, `data accuracy` 라벨
- 재현 가능한 fixture와 테스트
- 한국어 README + 짧은 영어 요약
- “태그 정규화/전투 중복 제거/표본 집계” 기술 글

개발자 별과 게임 이용자 검색은 다른 지표다. 둘을 합쳐 “사용자 수”로 보고하지 않는다.

## 3. 제품 안의 재방문 장치

홍보 전에 다음 경험을 우선한다.

1. 검색 성공 후 현재 태그를 공유할 수 있는 URL 또는 공유 버튼
2. 즐겨찾기 태그를 한 번에 다시 검색하기 쉬운 흐름
3. “마지막 수집 이후 25경기 정도 플레이했다면 다시 검색” 안내
4. 데이터 신선도와 저장 성공 여부 표시
5. 오류·데이터 제보 버튼을 결과 화면 가까이에 배치
6. 맵 추천에서 관련 팀 조합·카운터로 이어지는 내부 링크

공유 URL에 태그가 포함되면 공개 정보라는 이유만으로 무조건 안전하다고 보지 말고 사용자가 명시적으로 공유를 눌렀을 때만 만든다.

## 4. 6주 실행 일정

### 1주차 — 측정과 신뢰 기반

- 라이선스·제3자 권리·비공식 고지 확정
- CI와 첫 릴리스 후보 준비
- Search Console의 canonical 색인·검색어 기준선 저장
- 개인정보 비식별 이벤트 설계 승인
- 라이브 저장 흐름을 승인된 테스트 태그로 1회 검증

완료 조건: 검색 성공률, 최근 수집 시각, 페이지별 색인 상태를 과장 없이 설명할 수 있다.

### 2주차 — 전환 개선

- 홈 첫 화면에서 “무엇을 입력하고 무엇을 얻는지” 명확히 표시
- 결과의 데이터 신선도와 표본 설명 연결
- 피드백·GitHub·방법론 링크 노출
- 공유 또는 즐겨찾기 재검색 흐름의 작은 개선

완료 조건: 모바일과 데스크톱에서 첫 검색, 결과 확인, 피드백 이동이 막히지 않는다.

### 3주차 — 소규모 커뮤니티 실험

- 규칙을 확인한 커뮤니티 한 곳에 게시할 최종안을 사용자에게 보여줌
- 승인된 글 1건만 게시
- 캠페인별 UTM 사용
- 72시간 동안 유입·성공 검색·오류·피드백을 기록

판단: 방문만 늘고 검색 성공이 없으면 글을 더 뿌리지 않고 첫 화면과 메시지를 고친다.

### 4주차 — 유용한 콘텐츠와 검색 유입

- 방법론 설명 글 1개, 실제 기능 사용 사례 1개
- 주요 landing page 제목·설명·본문 중복 점검
- Search Console query/page 변화를 기준선과 비교
- 실제 데이터 오류 제보를 수정하고 공개 changelog 작성

### 5주차 — 재방문과 신뢰

- 즐겨찾기 사용성과 재검색 안내 개선
- 첫 공개 릴리스
- 7일 재방문과 반복 성공 검색을 확인
- 유지보수 응답 기록과 알려진 한계 갱신

### 6주차 — 증거 검토와 다음 채널 결정

- 채널별 `landing → search_succeeded → revisit/feedback` 비교
- 성과 없는 채널 중단, 성과 있는 채널만 업데이트 글 검토
- 사용자 수·태그 수·전투 수를 분리한 evidence log 작성
- Codex for Open Source 신청 시점을 A/B/C로 다시 판단

## 5. 실험 의사결정 규칙

초기 절대 목표를 합격 기준처럼 만들지 않는다. 첫 7일은 기준선을 수집한다. 이후 각 실험은 다음을 비교한다.

- 성공 검색률이 기준선보다 개선됐는가
- API/DB 오류율이 악화되지 않았는가
- 새 태그뿐 아니라 재검색과 실제 피드백이 생겼는가
- 특정 커뮤니티 유입이 표본 편향을 키웠는가
- 유지보수자가 7일 안에 응답 가능한 양인가

유입이 커도 오류율·불만·API 비용이 급증하면 홍보를 중단한다. 유료 광고는 검색 성공·재방문·비용 측정이 안정되기 전 6주 동안 사용하지 않는다.

## 6. Fan Content와 개인정보 보호

Supercell 정책상 비상업적 팬 가이드·앱은 조건부로 허용되지만, 공식인 것처럼 보이게 하면 안 되고 읽기 쉬운 비공식 고지가 필요하다. 광고·후원·도메인·자산 사용에도 제한이 있으므로 모든 홍보물에 현재 고지를 유지한다. 출처: <https://supercell.com/en/fan-content-policy/>

분석 도구는 개인 식별 정보를 전송하지 않고, 쿠키·광고 식별자를 쓰면 사용자 고지와 선택권을 검토한다. Google Analytics도 개인 식별 정보 전송을 금지하고 쿠키·식별자 처리에 관한 고지를 요구한다. 참고: <https://support.google.com/analytics/answer/6004245>
