# 데이터 산정 방식

## 무엇을 나타내는 통계인가

Brawl Status KR의 DB 통계는 **전체 Brawl Stars 이용자 통계가 아니다**. 사이트에서 플레이어 태그를 검색했을 때 받아 저장한 최근 전투의 누적 표본이다. 이용자 지역, 실력대, 검색 빈도, 특정 커뮤니티 유입에 따라 표본이 편향될 수 있다.

## 수집 단위

- 공식 전투 기록 응답은 최근 최대 25경기 범위다.
- 검색할 때마다 `POST /api/player/matches`가 현재 응답을 저장하려고 시도한다.
- 친선전 행은 저장될 수 있지만 메타와 누적 통계에서는 제외한다.
- 플레이어 태그는 공백 제거, 선행 `#` 제거, 대문자 변환 후 검증한다.
- 브라우저의 최근 검색·즐겨찾기는 서버 계정이 아니라 해당 브라우저 `localStorage`에만 저장한다.

## 전투 지문과 중복 방지

전투 지문은 다음 값을 `|`로 이어 만든다.

1. 전투 시간
2. 모드
3. 맵
4. 정렬된 참가자 태그 목록

DB는 `(player_tag, battle_time)`과 `(player_tag, battle_fingerprint)`를 각각 UNIQUE로 제한하고, 충돌 insert를 건너뛴다. 따라서 같은 태그의 같은 전투 재검색은 중복 저장되지 않는다.

동일 전투를 서로 다른 참가자 태그로 검색하면 태그별 행이 생길 수 있다. 팀전 메타 집계는 전투 지문별 최신 행 하나만 사용해 전체 참가자를 펼치므로 같은 팀전을 반복 계산하지 않는다.

## 승패 정규화

- 일반 팀전: API의 `victory`·`defeat`를 사용하고 그 외는 `draw`로 처리한다.
- 솔로 쇼다운: 순위 4위 이내를 승리로 처리한다.
- 듀오·트리오 쇼다운: 순위 2위 이내를 승리로 처리한다.
- 팀전 메타: 검색 플레이어가 속한 팀의 결과를 같은 팀 참가자에게 적용하고 상대 팀에는 반대 결과를 적용한다.
- 쇼다운: API가 모든 상대의 개별 결과를 제공하지 않으므로 검색된 플레이어 관점 행만 사용한다.

## 맵별 추천 점수

맵·브롤러 조합이 최소 5판일 때만 노출한다.

```text
승률 = floor(승리 수 / 표본 수 × 100)
추천 점수 = floor(승률 × 표본 수 / (표본 수 + 5))
```

신뢰도 표시는 다음 내부 구간을 사용한다.

- LOW: 5~19판
- MEDIUM: 20~49판
- HIGH: 50판 이상

신뢰도 점수는 `min(100, round(표본 수 / 50 × 100))`이다. 이 구간과 점수는 통계적 신뢰구간이 아니라 UI에서 표본 규모를 설명하기 위한 프로젝트 내부 기준이다.

## 캐시와 화면 차이

- 맵 메타 API는 최대 60초 캐시될 수 있다.
- `/status`와 플레이어 누적 DB 통계는 요청 시 DB를 읽는다.
- 외부 API 지연, DB 저장 실패, 캐시 시점 때문에 같은 순간에도 화면 간 값이 다를 수 있다.

## 알려진 한계

- 저장된 고유 태그 수는 고유 사용자 수가 아니다.
- 검색이 없는 기간의 전투는 수집되지 않는다.
- 중국 등 별도 API 생태계의 데이터가 동일하게 포함된다고 보장하지 않는다.
- 패치 직후 신규 모드·브롤러·맵 번역이 늦을 수 있다.
- 특정 커뮤니티 홍보가 표본의 지역·실력대 편향을 키울 수 있다.
- 5판은 노출 최소치일 뿐 충분한 대표성을 보장하지 않는다.

데이터 오류는 GitHub의 `데이터 정확성` 이슈 양식으로 제보할 수 있다. 실제 플레이어 태그는 필요한 최소 범위만 가려서 제공해야 한다.
