# 데이터 산정 방식

## 무엇을 나타내는 통계인가

Brawl Status KR의 DB 통계는 **전체 Brawl Stars 이용자 통계가 아니다**. 사이트에서 플레이어 태그를 검색했을 때 받아 저장한 최근 전투의 누적 표본이다. 이용자 지역, 실력대, 검색 빈도, 특정 커뮤니티 유입에 따라 표본이 편향될 수 있다.

## 수집 단위

- 공식 전투 기록 응답은 최근 최대 25경기 범위다.
- 검색할 때마다 `POST /api/player/matches`가 현재 응답을 저장하려고 시도한다.
- 친선전 행은 저장될 수 있지만 메타와 누적 통계에서는 제외한다.
- 플레이어 태그는 공백 제거, 선행 `#` 제거, 대문자 변환 후 검증한다.
- 브라우저의 최근 검색·즐겨찾기는 서버 계정이 아니라 해당 브라우저 `localStorage`에만 저장한다.

## 전투 지문과 중복 방지

전투 지문은 다음 값을 `|`로 이어 만든다.

1. 전투 시간
2. 모드
3. 맵
4. 정렬된 참가자 태그 목록

DB는 `(player_tag, battle_time)`과 `(player_tag, battle_fingerprint)`를 각각 UNIQUE로 제한하고, 충돌 insert를 건너뛴다. 따라서 같은 태그의 같은 전투 재검색은 중복 저장되지 않는다.

동일 전투를 서로 다른 참가자 태그로 검색하면 태그별 행이 생길 수 있다. 일반 2팀 전투 메타 집계는 전투 지문별 최신 행 하나만 사용한 뒤 양 팀 참가자를 모두 펼치므로 같은 팀전을 반복 계산하지 않는다.

## 승패 정규화

- 일반 팀전: API의 `victory`·`defeat`를 사용하고 그 외는 `draw`로 처리한다.
- 솔로 쇼다운: 순위 4위 이내를 승리로 처리한다.
- 듀오·트리오 쇼다운: 순위 2위 이내를 승리로 처리한다.
- 팀전 메타: `teams`가 정확히 2개인 일반 팀전만 양 팀으로 확장한다. 검색 플레이어가 속한 팀의 결과를 같은 팀 참가자에게 적용하고 상대 팀에는 반대 결과를 적용한다.
- 팀 조합: 전투 지문별 대표 행 하나에서 두 팀 조합을 모두 표본화한다.
- 카운터: 선택 브롤러가 검색 플레이어의 팀에 있었는지 상대 팀에 있었는지를 먼저 복원한 뒤 상대 브롤러의 결과를 계산한다.
- 쇼다운: 듀오·트리오처럼 `teams` 배열이 있더라도 여러 팀의 개별 승패를 임의로 만들지 않고 검색된 플레이어 관점 행만 사용한다.

## 맵별 추천 점수

맵·브롤러 조합이 최소 5판일 때만 노출한다.

```text
승률 = floor(승리 수 / 표본 수 × 100)
추천 점수 = floor(승률 × 표본 수 / (표본 수 + 5))
```

신뢰도 표시는 다음 내부 구간을 사용한다.

- LOW: 5~19판
- MEDIUM: 20~49판
- HIGH: 50판 이상

신뢰도 점수는 `min(100, round(표본 수 / 50 × 100))`이다. 이 구간과 점수는 통계적 신뢰구간이 아니라 UI에서 표본 규모를 설명하기 위한 프로젝트 내부 기준이다.

화면은 이 구간을 **표본 규모**로 표시하며, 50판만으로 100% 확실하다고 보일 수 있는
백분율 막대는 사용하지 않는다. 각 카드의 `추천 기준 보기`에서는 승률·표본 감점 기준과
기록된 승리/전체 표본으로 계산한 양측 95% Wilson 구간을 보여 준다. 무승부는 기존
승률과 동일하게 승리가 아닌 표본으로 포함한다. 계산은 반올림한 승률이 아닌 원본
승리 수를 사용한다. 독립적인 이항 표본을 가정하므로 검색 유입 편향이나 같은 경기
참가자 간 상관을 보정하지 못하며, 다음 경기의 승률이나 전체 이용자의 승률을
보장하지 않는다. 수식 참고: https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm

`X-Meta-Refreshed-At`과 화면의 갱신 시각은 **DB 집계가 갱신된 시점**이다.
마지막 경기 시각이나 패치 반영 여부가 아니다. 카드의 **최근 7일 표본**과
**마지막 경기**는 같은 30일 집계에서 구한 경기의 최신성 정보다. 미래 시각의
기록은 집계에서 제외한다. 최근 7일 표본이 5건 미만이면 현재 맵 환경을 충분히
반영하지 못할 수 있다고 안내한다. 5건은 안내 기준이며 대표성을 보장하지 않는다.

최근 경기 가중치와 평균으로의 표본 보정 후보를 실제 기록의 날짜를 나눠
비교했으나 순위 개선을 확인하지 못해 현재 점수를 유지한다.
[2026-10-21 비교 결과](RECOMMENDATION_EVALUATION_20261021.md)를 참고한다.
경기별 시간 가중치·패치별 초기화는 적용하지 않았으며, 새 표시를 추천 승률
향상이 검증된 것으로 부르지 않는다.

## 캐시와 화면 차이

- 맵 메타는 비공개 `meta_brawler_quality_snapshot`을 15분마다 갱신하는 DB 집계와 300초 Next Data Cache를 사용한다.
  45분 넘게 오래된 집계는 제공하지 않는다. 팀 조합·카운터는 별도의 캐시를 사용한다.
- `/status`와 플레이어 누적 DB 통계는 요청 시 DB를 읽는다.
- 외부 API 지연, DB 저장 실패, 캐시 시점 때문에 같은 순간에도 화면 간 값이 다를 수 있다.

## 알려진 한계

- 저장된 고유 태그 수는 고유 사용자 수가 아니다.
- 검색이 없는 기간의 전투는 수집되지 않는다.
- 중국 등 별도 API 생태계의 데이터가 동일하게 포함된다고 보장하지 않는다.
- 패치 직후 신규 모드·브롤러·맵 번역이 늦을 수 있다.
- 특정 커뮤니티 홍보가 표본의 지역·실력대 편향을 키울 수 있다.
- 5판은 노출 최소치일 뿐 충분한 대표성을 보장하지 않는다.
- 누적 활동의 일별 그래프는 최근 최대 60개 활동일만 반환하지만 전체 저장 전투 수, 기록 일수, 트로피 변화, 자주 한 맵·모드는 전체 저장 기간 기준이다.

데이터 오류는 GitHub의 `데이터 정확성` 이슈 양식으로 제보할 수 있다. 실제 플레이어 태그는 필요한 최소 범위만 가려서 제공해야 한다.
