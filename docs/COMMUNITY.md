# 트롤 박제 커뮤니티

`/community`와 9개 언어 경로에서 증거가 있는 트롤 박제와 반론·정정 댓글을 받습니다. 공개된 글은 비회원도 읽을 수 있으며, 글·댓글 작성은 기존 Google 계정으로 로그인하고 가입 절차를 완료한 회원만 가능합니다. 기존 전적 검색과 미니게임의 비회원 이용에는 영향을 주지 않습니다.

## 게시 기준과 증거

- 단순 실력 부족, 픽, 승률만으로 제보할 수 없습니다. 고의적인 경기 방해를 의심할 구체적인 맥락과 증거가 필요합니다.
- 글에는 사진 또는 공개 사진·영상 링크를 합쳐 1~3개 첨부합니다. 사진만으로도 접수할 수 있습니다. 링크는 YouTube, Vimeo, Imgur, Postimages만 받으며 영상 직접 업로드·원격 URL 수집은 지원하지 않습니다.
- 글·댓글에서 JPG, PNG, WebP 사진을 선택·미리보기·삭제할 수 있습니다. 장당 원본 8MB 이하, 브라우저에서 최대 1600px·2MB 이하로 변환한 뒤 서버에서도 실제 형식·픽셀 수를 검사하고 WebP로 재인코딩합니다. 위치·EXIF 메타데이터와 원본 파일명은 저장하지 않습니다. 사진 속 개인정보를 자동으로 가리는 기능은 아니므로 제출 전에 직접 가려야 합니다.
- 댓글은 일반 의견 또는 반론·정정 요청으로 구분합니다. 댓글의 증거 사진·링크는 선택 사항입니다.
- 욕설, 협박, 개인정보, 집단 공격 유도는 허용하지 않습니다. 관련 없는 플레이어의 정보는 가려야 합니다. 공개 승인은 공식 제재나 게임 계정 소유권 확인을 뜻하지 않습니다.
- 흔한 욕설은 표시 단계에서 마스킹합니다. 자동 필터가 의도나 사실관계를 판단하지는 않으며 운영자가 원문과 증거의 전후 맥락을 검토합니다.

## 검토와 공개 범위

글과 댓글 모두 `pending`으로 접수됩니다. 승인 전에는 작성자와 운영자만 볼 수 있습니다. 상위 글 작성자도 타인의 미승인 댓글은 볼 수 없습니다. 작성자는 글 목록의 **내 글**에서 상태와 검토 사유를 확인합니다. 댓글 상태와 사유는 해당 글에서 확인합니다.

기존 운영자 허용 목록에 등록된 계정은 계정 메뉴의 **커뮤니티 검토** 또는 `/admin/community`로 들어갑니다. 증거 링크, 고의성 판단에 필요한 맥락, 신상 정보, 과도한 욕설, 공격 유도와 반론을 확인하고 **공개 승인 / 반려 / 공개 중단** 및 사유를 입력합니다. 공개 결정과 운영자 참조는 검토 기록에 남습니다. 사유는 해당 작성자에게도 표시되므로 내부 비밀이나 다른 회원의 개인정보를 적지 않습니다.

반론에 근거가 있으면 원글의 공개를 중단하고 재검토합니다. 반론·정정 댓글도 같은 검토 목록으로 들어옵니다. 댓글을 승인하려면 상위 글이 공개 상태여야 합니다. 이미 철회된 내용이나 다른 운영자가 갱신한 이전 버전은 승인할 수 없습니다.

## 계정과 보관

공개 화면에는 비공개 계정 닉네임·이메일·UUID 대신 자동 생성한 커뮤니티 별명 `Loop-XXXXXXXXXXXX`를 표시합니다. 게임 계정 소유권은 인증하지 않으며 실제 인물의 신원을 요구하지 않습니다.

작성자의 **철회**는 공개를 중단하는 기능입니다. 원문·증거 링크·검토 기록은 검토와 정정 처리를 위해 남습니다. 계정 삭제 시 해당 계정의 글·댓글·커뮤니티 프로필은 외래 키로 삭제되고, 함께 삭제되는 글에 달린 댓글도 삭제됩니다. 다른 글에 남은 검토 기록의 삭제된 운영자 참조는 비웁니다.

커뮤니티 6개 테이블(사진 메타데이터·객체 목록 포함)은 기존 계정 전용 암호화 백업에 포함됩니다. 사진 원본 바이트는 이 DB 백업에 포함되지 않고 비공개 Vercel Blob에만 저장됩니다. 별도의 사진 바이트 백업은 아직 구성하지 않았습니다. 계정 삭제 후 남아 있는 암호화 백업에는 기존 보관 기간이 적용됩니다. 복구 시 삭제 명세를 다시 적용해 삭제한 계정과 커뮤니티 내용을 되살리지 않습니다. 개인정보·이용약관 화면에도 이 범위를 안내합니다.

사진은 공개 Blob URL 대신 서버의 접근 검사 경로로만 제공합니다. 미승인 사진은 작성자·운영자만 볼 수 있고, 댓글 사진은 댓글과 상위 글이 모두 공개여야 비회원이 볼 수 있습니다. 숨김·철회·계정 삭제 즉시 해당 공개 접근이 차단됩니다. 응답은 항상 private/no-store이며 Next 이미지 최적화 캐시를 통하지 않습니다.

미제출 사진은 24시간 후 접근·첨부가 만료됩니다. 기존 일일 유지보수 작업이 만료 사진과 계정 삭제·선택 취소 후 남은 객체를 정리합니다. 객체 목록은 계정과 별도로 남아 실제 바이트 삭제에 실패하면 다음 실행에서 재시도합니다. 한 번에 100개를 처리하므로 정리 대기량·장애가 있으면 물리적 삭제가 지연될 수 있습니다. 계정 백업 복원 후에도 같은 정리 절차를 실행합니다.

## 서버 보호와 배포

- 세션, 가입 완료, 요청 계정 일치, 동일 출처를 서버에서 확인합니다. 작성자·승인 상태를 클라이언트 입력으로 받지 않습니다.
- 회원당 글 1일 3개, 댓글 1시간 20개를 공유 DB 카운터로 제한합니다.
- 사진은 회원당 정상 업로드 1시간 9장, 파일 검사 시도 1시간 60회로 제한합니다. 실패한 글 입력·만료된 사진은 글 작성 한도를 소모하지 않습니다.
- 입력 검증을 통과한 요청에 작성 제한을 적용합니다. 제목·본문·증거 링크·동의 항목의 입력 오류는 작성 횟수를 소모하지 않으며, 화면에서 해당 항목과 조건을 안내합니다. 접수 후에는 작성자에게 검토 접수 메시지와 대기 상태를 표시합니다.
- RLS와 권한 회수로 `anon`·`authenticated`의 DB 직접 접근을 차단합니다. 기존 서버 DB 연결로만 접근합니다.
- 개인별 응답은 `private, no-store`, 글과 댓글 경로는 검색 엔진 `noindex, nofollow`로 제공합니다.
- 기존 계정·운영자 설정과 private Blob 저장소를 사용합니다. Vercel 프로젝트의 Production/Preview에 저장소를 연결해 `BLOB_STORE_ID`와 자동 OIDC 자격 증명을 공급합니다. Vercel 외부에서는 서버 전용 `BLOB_READ_WRITE_TOKEN`을 사용할 수 있습니다. 브라우저에 저장소 자격 증명을 노출하지 않습니다.
- `0020_community_posts_comments.sql`, `0021_community_photo_evidence.sql`을 기존 계정 마이그레이션 실행기로 먼저 적용한 뒤 앱을 배포합니다. Supabase에서 직접 적용할 경우 앱의 `account_schema_migrations`에도 동일 SQL의 정규화된 체크섬을 함께 기록해야 합니다.

검증은 입력·인증 단위 테스트, 일회용 PostgreSQL의 공개 범위·검토 충돌·계정 삭제 검사, 암호화 백업 복구 및 실제 로그인 세션을 쓰는 커뮤니티 E2E로 구성합니다. 테스트 데이터는 격리한 로컬·CI DB에만 만듭니다.
