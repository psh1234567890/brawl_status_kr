# 운영 API 성능 집계 (PR #93)

- 대상: 공개 프로필, 전투 기록 읽기·쓰기, 스킨, 메타·카운터·팀 추천 API의 고정된 7개 route_key.
- 저장: 시간대 × route_key별 요청 합계, HTTP 404·429·기타 4xx·5xx·정상 구간 합계, 처리시간의 합계와 7개 비중복 응답 시간 구간. 개별 요청·검색 태그·IP·계정·쿠키·요청 ID·User-Agent·URL은 DB에 저장하지 않음.
- 집계 적용: 운영 환경에서만. 기존 방문 통계 opt-out 쿠키를 설정한 요청은 집계하지 않음. 응답 후 Next after()로 저장하므로 DB 집계 쓰기 장애가 공개 API 응답의 성공 여부를 바꾸지 않음.
- 기간: 최근 24시간 또는 최근 7일. 시간대별 원본 집계 행은 최대 30일 보존 후 pg_cron으로 삭제. 날짜 이전 기록을 소급해 만들어내지 않음.
- 표시: 평균 = 응답시간 합계 / 요청 횟수. 서버 오류율 = 5xx / 전체 요청. 429율 = 429 / 전체 요청. P95 정확한 수치가 아니라 구간: 일련의 버킷을 누적하여 95% 요청이 속한 시간대 구간을 표시.
- 공개 URL /api/admin/usage는 기존 비공개 서버 인증과 운영자 허용 목록을 통과한 경우에만 집계값을 반환. 응답은 private, no-store 및 noindex. 신규 테이블도 analytics_private 스키마와 REVOKE 및 RLS로 직접 공개 조회 차단.
- 운영 배포 순서: drizzle/0019_private_api_performance_hourly.sql을 DB에 적용·검증 후 API 집계 코드 운영 배포. DB 마이그레이션 누락 시 카운터 쓰기 실패는 숨기고 운영 로그에 고정된 에러 이벤트만 기록함.
- 이 지표는 서버의 응답시간 기준이며 사용자의 화면에 처음 프로필이 나타나는 시간(클라이언트 렌더링)은 포함하지 않음.
