# 개인정보와 측정 원칙

이 문서는 코드와 운영 결정을 맞추기 위한 개발 문서이며 법률 자문이 아니다. 실제 배포 설정이 바뀌면 사이트의 개인정보처리방침도 함께 갱신해야 한다.

## 현재 처리하는 데이터

- 사용자가 입력한 공개 플레이어 태그
- 공식 API에서 받은 공개 프로필과 최근 전투 기록
- DB에 저장된 전투 시간, 모드, 맵, 브롤러, 결과, 원본 전투 JSON
- 악성 요청 방지를 위한 IP 기반 메모리 rate-limit 키
- 계정 기능 활성화 시 요청 제한과 악용 방지를 위해 계정 ID와 신뢰된 요청 IP에서 만든 HMAC 해시. 원본 값은 rate-limit 테이블에 저장하지 않는다. 제한 창이 끝나면 해당 행은 더 이상 요청 제한 판정에 쓰이지 않으며, 만료 행은 예약된 정리 작업에서 물리 삭제되므로 다음 정리 실행 전까지 데이터베이스에 남아 있을 수 있다. 사용자별 해시는 계정 삭제 transaction에서 제거한다.
- 브라우저에 저장되는 최근 태그와 즐겨찾기, 그리고 전체 보유 스킨 보조 조회가 성공한 경우 최대 24시간 유지될 수 있는 로컬 스킨 캐시
- 문의 시 사용자가 보낸 이메일과 내용
- 운영자가 Brawlace 보조 조회를 명시적으로 활성화한 경우 Brawlace에 전달되는 공개 플레이어 태그와, Jina Reader fallback도 별도로 활성화한 경우에만 fallback 요청에 포함되는 동일 태그
- 맵·모드·브롤러·이벤트 메타데이터를 위한 BrawlAPI 요청. 이 경로에는 플레이어 태그를 보내지 않는다.
- 브롤러·맵·배지 등 원격 이미지를 불러오기 위한 Brawlify CDN 요청

현재 저장소 코드에는 일반 웹 분석 SDK가 없다. Google AdSense 환경 변수는 선택 사항이며, 실제 광고가 활성화되면 쿠키·광고·동의 설명을 실제 설정과 맞춰야 한다.

보유 스킨 보조 조회는 기본 비활성이다. 운영자가 관련 조건을 검토하고 `BRAWLACE_SKIN_LOOKUP_ENABLED=true`를 명시한 경우에만 Brawlace를 조회한다. Jina Reader fallback도 기본 비활성이며, `BRAWLACE_JINA_READER_ENABLED=true`를 추가로 명시한 경우에만 직접 조회 실패 후 같은 공개 페이지를 읽는 보조 경로로 사용한다. 활성화 시 공개 플레이어 태그가 해당 외부 요청에 포함될 수 있다. 전체 보유 스킨 보조 조회가 성공한 경우 해당 결과는 같은 브라우저의 `localStorage`에 최대 24시간 임시 캐시될 수 있으며, 운영자가 보조 provider를 비활성화한 경우 이 캐시는 조회에 사용하지 않는다.

## 데이터 최소화

- 분석 이벤트에 플레이어 태그 원문을 보내지 않는다.
- 방문자 수와 태그 수를 연결하지 않는다.
- 운영 DB 덤프와 실제 태그를 공개 fixture로 사용하지 않는다.
- UTM은 채널·캠페인만 기록하고 개인 식별 정보를 넣지 않는다.
- 오류 로그에 API 키, DB URL, 전체 API 응답을 남기지 않는다.

## 보관과 삭제

현재 자동 TTL 삭제는 적용하지 않는다. 전투 기록과 통계 데이터는 서비스 제공과 통계 품질 유지를 위해 서비스 운영 기간 동안 보관하며, 서비스 종료·운영 데이터 재설정 또는 검증된 기록 요청을 처리하는 경우 삭제될 수 있다. 문의 메일은 문의 처리와 분쟁 대응에 필요한 기간 동안 보관한다.

공개 플레이어 태그만으로 소유자를 확인할 수 없으므로 무인증 `DELETE /api/player/history`와 화면의 자동 삭제 버튼을 제거했다. 기록 관련 요청은 운영자가 문의 메일에서 개별 검토한다. 장기적으로 계정이나 별도 소유권 증명 없이 자동 삭제 기능을 다시 열지 않는다.

## 이용자 확보 측정 시 허용 범위

권장 집계 이벤트는 페이지·캠페인·성공 여부·오류 종류·날짜 수준이다. 다음 값은 전송하지 않는다.

- 플레이어 태그
- 플레이어 이름
- 이메일
- API 키
- DB 식별자
- 전체 referrer query string

분석 도구를 도입하기 전 쿠키 사용, 보관 기간, 제3자 제공, opt-out 또는 동의 필요성을 확인하고 사이트 방침에 반영한다.

## 계정 MVP의 데이터 범위

계정 기능은 기본 off이며 필요한 정책과 OAuth 설정이 준비되어 서버 플래그로
활성화된 경우에만 제공한다. 활성화 시 Google 로그인으로 확인한 provider
subject, 비공개 이메일, 내부 UUID, 중립 닉네임, 사용자가 선택한 대표 플레이어
태그, 세션, Mini Game 최고 기록을 저장한다. Google 실명과 사진은 프로필 기본값으로
복사하지 않는다. 이메일과 provider subject는 공개 DTO·공개 프로필·랭킹·일반
로그에 넣지 않는다.

대표 태그는 기본값과 개인화 편의를 위한 값일 뿐 게임 계정 소유권 검증이 아니다.
사용자는 한 브라우저의 legacy 최고 기록을 명시적으로 가져올 수 있다. 동기화
대기 operation은 브라우저 IndexedDB에 UUID별로 보관될 수 있다. 모든 synced PB는
클라이언트 보고값이며 검증된 경쟁 결과가 아니다.

활성 DB의 계정 데이터는 계정 삭제 transaction에서 제거되고, 공개 전투 기록은
태그만으로 연결되므로 그대로 남는다. 삭제 시 `public` tombstone과 public-schema
dump에 포함되지 않는 `account_safety.deletion_ledger`에 같은 삭제 표식을 남긴다.
백업 helper는 활성 삭제 표식을 HMAC 서명된 deletion manifest로 별도 내보내며,
복구 helper와 전용 재적용 script는 복구된 계정 행을 공개하기 전에 해당 manifest를
검증·재적용한다. 실제 백업 보존 일수와 deletion manifest 보존 일수는 운영 환경
설정으로 명시하며 manifest 보존 기간은 백업 보존 기간보다 길어야 계정 기능이 열린다.

연령·국가별 이용 자격은 운영자가 별도 정책 검토 후 구조화된 규칙과 10개 언어의
안내문을 함께 설정해야 한다. 현재 구현은 정확한 생년월일이나 국가 값을 계정 DB에
저장하지 않고 사용자의 명시적 self-attestation만 기록한다. 보호자 동의 workflow는
구현하지 않았으므로 구조화 규칙의 `guardianConsent`는 `not-supported`만 허용한다.
Google 로그인은 나이 확인이나 보호자 동의를 대신하지 않으며, 운영자가 실제 기준을
확정하지 않은 상태에서는 계정 기능이 fail-closed로 유지된다.
